# RESPAWN 2.0: персональна гра для всіх (план, гілка `dev`)

Мета: щоб RESPAWN підходив будь-кому, хлопцю чи дівчині, з будь-якими цілями, і лишався простим. У всіх ті самі 6 сфер, а гнучкість дають квести, скіли й модулі, які людина обирає сама. Прогрес тих, хто вже грає, переноситься без втрат. Архітектура одразу розрахована на друзів, перегляд статистики й спільні плани.

**Прийняті рішення (14.11.2026):**
- **6 сфер фіксовані для всіх:** Тіло, Розум, Гроші, Спокій, Люди, Порядок. Їх не можна замінювати чи перейменовувати.
- Звертання тільки «Він / Вона», без нейтрального варіанта.
- Dev тестуємо тільки локально.
- Вкладки: 4 зараз (База · Квести · Сфери · Шафка). 5-те місце зарезервоване під «Друзі».

---

## 1. Принципи

1. **Чужий прогрес не губимо.** Схема збереження тільки доповнюється. Старі дані не переписуємо, а читаємо через таблицю відповідностей. Перед міграцією робимо бекап.
2. **Простота.** Основний цикл: квест → XP → рівень → скіни. Сфери однакові для всіх, налаштовувати їх не треба. Решта (гроші, зал, фокус, розминка) — модулі, які можна ввімкнути.
3. **Гнучкість у змісті, а не в структурі.** Що саме входить у «Розум» чи «Тіло», людина вирішує своїми квестами й скілами.
4. **Стать змінює тільки граматику та стартовий вигляд.** Сфери, квести й скіни однакові для всіх.
5. **Скіни унісекс.** Жодних замків за статтю.
6. **Офлайн спочатку, соціалка окремим шаром.** Особистий сейв і далі живе на пристрої та в Telegram. Сервер (у майбутньому) зберігатиме тільки друзів, публічні картки й спільні плани.

## 2. Як не зламати прогрес (найважливіше)

**Де зараз живуть збереження:**
- `localStorage['respawn.v1']`. Він прив'язаний до origin `ketalias.github.io`, тобто до всього домену, а не тільки до `/respawn/`.
- Telegram CloudStorage (окремо для кожного бота): чанки `c0…cN` + `meta`. `syncCloud()` бере той сейв, де `updatedAt` новіший.

**Ризики й рішення:**

| Ризик | Що станеться | Рішення |
| --- | --- | --- |
| Dev викладено на тому ж домені (`ketalias.github.io/щось`) | Dev-версія читає й мігрує **справжні** сейви з `localStorage` | Dev тільки локально: `localhost` — окремий origin, тож окремий ключ сховища не потрібен |
| Старий клієнт (закешований у Telegram на іншому пристрої) відкриває сейв v3 | `hydrate()` перекидає квести з нових сфер (`mind`, `calm`, `people`) у «Дисципліну» й викидає нові ключі `stats`. `CATS[k.cat].icon` у скілах падає. Потім він заливає «новіший» зламаний сейв у хмару | **Етап 0**: хотфікс на `main` за 1–2 тижні до релізу. Старий код має терпіти невідомі сфери |
| Перейменування id | Куплені скіни «зникають» | Id предметів ніколи не змінюються (`slot:key` в `owned` і `eq`) |
| Злиття старих категорій (Математика + Інженерія → Розум) | Переписування квестів і статів може щось загубити | Старі значення не переписуємо: `q.cat = 'math'` лишається в сейві, а показується як «Розум» через `ALIAS` (розділ 3) |

**Етап 0, «щеплення» (маленький хотфікс на `main`).** ✅ На `main` з 14.11.2026, версія v1.2 (коміт `2c1fda3`).
- `hydrate()` залишає в `stats` невідомі ключі й не чіпає невідомі `q.cat`.
- Усюди, де стоїть `CATS[x]`, додаємо фолбек `{ name: 'Інше', icon: 'star' }` (`questCard`, `mind.js` ×5).
- Невідомі поля всередині `days[k]` і квестів не зачіпаються (перевірено).
- Невідома аура на Базі більше не дає білого екрана. Невідома складність квесту → «Норм».
- Версія сейву (`v`) не знижується.
- Піднімаємо `VERSION` у `sw.js`.

**Бекап і тести:**
- Перед першою міграцією на v3 записуємо копію в `localStorage['respawn.v1.bak2']`. Експорт/імпорт у профілі вже є.
- `tools/migrate-test.mjs` проганяє `hydrate()` на фікстурах: сейв v1 (str/int/vit), справжній сейв автора, сейв з грошима/тренуваннями/скілами, порожній сейв.
  - Перевіряє, що `xp, coins, owned, eq, ach, streak, counters, money.log, workouts, prs` не змінились.
  - Перевіряє, що сума XP по сферах до і після однакова.
- Окремий тест «старий клієнт»: сейв v3 → `hydrate()` з етапу 0 → назад у v3, нічого не загубилось.

## 3. Шість сфер (фіксовані)

| id | Сфера | Що туди входить | Модуль (за бажанням) |
| --- | --- | --- | --- |
| `body` | Тіло | спорт, сон, вода, харчування, здоров'я | Зал (журнал тренувань) |
| `mind` | Розум | навчання, читання, мови, математика, код | Фокус-сесії, Розминка мозку |
| `biz` | Гроші | робота, бізнес, кар'єра, фінанси | Бос місяця |
| `calm` | Спокій | відпочинок, медитація, щоденник, хобі для душі | — |
| `people` | Люди | сім'я, друзі, стосунки, нетворкінг | — |
| `dis` | Порядок | дім, режим, рутина, сила волі | — |

- На радарі в профілі вони складаються в шестикутник. Назви, іконки й кольори однакові для всіх.
- Старі id `biz`, `body` і `dis` лишаються як є. `dis` тепер показується як «Порядок» замість «Дисципліна».

**Де гнучкість:**
- **Квести.** Свої назви. Для кожної сфери є 6–10 готових квестів, які додаються одним тапом. Квест створюється в 2 тапи: назва + сфера. Складність за замовчуванням «Норм», решта під «Більше».
- **Скіли (фокус-сесії)** з власними назвами («Математика», «Програмування», «Гітара»). Тепер скіл можна прив'язати до будь-якої з 6 сфер, а не тільки до 3, як зараз (`SKILL_CATS`).
- **Модулі** вмикаються за бажанням. Кожен нараховує XP у свою сферу: Бос місяця → Гроші, Зал → Тіло, Розминка → Розум, Фокус → сфера скіла.

**Старі категорії → нові сфери (без переписування даних):**
```js
// data.js
export const ALIAS = { math: 'mind', eng: 'mind' };            // v1-ключі str/vit/int, як і раніше, згортаються в hydrate()
export const sphereOf = k => (CATS[k] ? k : ALIAS[k] || k);     // невідомий ключ (з новішої версії) лишається як є
// XP сфери = власний ключ + усі старі ключі, що на неї вказують
export const sphereXP = (stats, id) => Object.entries(stats || {}).reduce((a, [k, v]) => a + (sphereOf(k) === id ? +v || 0 : 0), 0);
```
- Квест зі старим `cat: 'math'` показується в Розумі. Якщо людина відредагує квест, він збережеться вже з `mind`.
- Нове XP пишеться тільки в нові ключі. Старі `stats.math` і `stats.eng` лишаються в сейві як були й додаються до Розуму при показі.

**Для тих, хто вже грає:**
- Математика + Інженерія → **Розум**. Розрізнення не губиться: воно лишається в скілах (фокус-сесіях) з тими самими назвами й годинами.
- Дисципліна → **Порядок**.
- Гроші й Тіло → без змін.
- **Спокій** і **Люди** — нові сфери, стартують з нуля.
- Ачівки «10 годин математики» / «10 годин інженерії» вже зароблені — лишаються. Для решти: 10 і 50 годин фокусу в Розумі. Id ачівок і скіни за них (халат, каска) не змінюються.
- Ачівка «Гармонія» (усі сфери до LV 5) тепер рахується по 6 сферах. Якщо вже отримана, лишається.

## 4. Стать: звертання й тіло

**Звертання** — один вибір в онбордингу: «Як до тебе звертатись?» Він / Вона.

- **Граматика.** Хелпер `g('Закрив угоду', 'Закрила угоду')`. Треба перевірити близько 20–30 рядків: бізнес-дії («Написав ліду», «Здав роботу»), тости («Відпочив»), «Готовий до підходу?», «Шукай сам», онбординг. Де можна, пишемо нейтрально.
- **Ранги в двох родах:**

| LV | Він | Вона |
| --- | --- | --- |
| 1 | NPC | NPC |
| 3 | Новачок | Новачка |
| 6 | Гравець | Гравчиня |
| 10 | Боєць | Бійчиня |
| 15 | Ветеран | Ветеранка |
| 20 | Еліта | Еліта |
| 30 | Майстер | Майстриня |
| 40 | Легенда | Легенда |
| 50 | Фінальний бос | Фінальний бос (ігровий термін) |

- Старим акаунтам нічого не змінюється (лишаються поточні форми), доки людина сама не обере у «Що нового».
- Звертання потрапляє в публічну картку, щоб друзі бачили правильні форми («Оля закрила 5 квестів»).

**Тип тіла** — окремий вибір у Шафці (тіло A / тіло B), незалежно від звертання.
- Тіло B: вужчі плечі, талія, стегна. Еволюція рангу 0→3 означає підтягнутість і атлетичність, а не масу.
- Технічно: `geo()` у `sprite.js` отримує профіль тіла. `thw()` уже рахує ширину торсу по рядках, тож більшість верхів адаптуються самі. Предмети з дрібними деталями (костюм, халат, броня) перевіряємо вручну.

## 6. Простота інтерфейсу

**Вкладки:**
- **Зараз 4:** База · Квести · Сфери · Шафка. Профіль, як і раніше, відкривається через аватар у шапці.

**Ачівки.** Лічильник «x / y» рахує тільки ачівки увімкнених модулів. Зароблені ніколи не зникають. Додаємо ачівки сфер: «Сфера до LV 5 / 10», «Усі 6 сфер до LV 3».

1. Ім'я + «Як до тебе звертатись?»

3. Стартові квести: 6 сфер, під кожною 2–3 готові квести. Відмічаєш ті, що підходять (рекомендовано 3–6). Модулі пропонуються там само («Ведеш тренування? Увімкни Зал»).

### «Що нового» для тих, хто вже грає (одне вікно, можна пропустити)

## 7. Модель даних v3 (тільки доповнення)

```js
{
  v: 3,
  profile: { g: 'm' | 'f' | null },          // null = старий акаунт, ще не обирав → поточні форми
  stats: { body, mind, biz, calm, people, dis,  /* + старі math, eng — не чіпаємо, додаються через ALIAS */ },
  mods: { money: true, gym: true, focus: true, drill: true, home: ['money', 'drill'] },
  days: { '2026-11-14': { xp: 120, q: 4, w: 1, s: { body: 60, biz: 60 } } },  // нове: s = XP по сферах за день
  quests: [ { /* …як зараз…, */ plan: null } ],   // нове: посилання на спільний план (майбутнє)
  skills: [ { /* …як зараз…, cat — будь-яка з 6 сфер */ } ],
  eq: { /* …як зараз…, */ body: 'a', detail: null },
  looks: [ /* { name, eq } ×3 */ ],
  privacy: { card: 'friends', spheres: true, heat: true, money: false, quests: false }, // діє, коли з'являться друзі
}
```

- `CATS` лишається статичним, тепер це 6 сфер. Додаються `ALIAS`, `sphereOf()` і `sphereXP()`. Усі місця, що читають `CATS[x]` чи `stats[x]`, переходять на них.
- `grant()` пише XP у `sphereOf(cat)` і в `days[k].s`.
- `days[k].s` пишеться тільки з v3 далі, старі дні не чіпаємо. Дні, старші за рік, згортаємо до `{ xp, q, w }`, щоб CloudStorage не розросталась.
- Міграція v2→v3 мінімальна: додати `profile`, `mods` (старим акаунтам усе ввімкнено й закріплено), `privacy`. Квести й стати не переписуються.

## 8. Соціальна частина: що закладаємо вже зараз

Друзів, статистики й спільних планів у v2.0 ще **не буде**, але v2.0 проєктуємо так, щоб їх можна було додати без нової міграції сейвів. Фіксовані сфери тут дуже допомагають: у всіх однакова шістка, тож порівнювати й ділитися квестами можна напряму.

### Що з'явиться пізніше
- **Друзі.** Запрошення посиланням у Telegram (`t.me/<bot>/<app>?startapp=f_<код>`), список друзів, картка кожного: персонаж у скінах, LV і ранг, 6 сфер, стрік, ачівки, теплова карта.
- **Статистика.** «Цього тижня»: XP по сферах у тебе та друзів, хто тримає стрік.
- **Спільні плани.** 1–5 квестів, кілька людей і строк (наприклад, 30 днів). Кожен відмічає у себе, усі бачать прогрес команди. Якщо всі закрили день, кожен отримує бонус «Командний ідеальний день». Квест плану має сферу з тієї самої шістки, тож у кожного він потрапляє туди ж.

### Архітектура
```
Пристрій (як зараз)                    Сервер (майбутнє, окремий шар)
────────────────────                   ──────────────────────────────
localStorage + Telegram CloudStorage   users     (tg_id, name, g, card, card_at)
повний особистий сейв                  friends   (a, b, status)
            │                          plans     (id, owner, title, quests, until)
            │  публікує картку,        members   (plan, user)
            │  чек-іни квестів плану   checkins  (plan, pq, user, d)
            └───────────────────────►  доступ: бачиш тільки друзів і свої плани
```
- **Особа = Telegram user id.** Сервер перевіряє підпис `initData` (HMAC токеном бота). Логінів і паролів немає.
- Хто відкриває сайт поза Telegram, грає як зараз, а для соціалки підключає Telegram.
- **Публічна картка — чиста функція** `publicCard(S, privacy)`. Без сум грошей і назв квестів (якщо людина сама не дозволить). Сервер не бачить особистого сейву.
- **Офлайн.** Чек-іни квестів плану складаються в чергу всередині сейву й відправляються, коли з'явиться мережа.
- **Бекенд:** Supabase (Postgres + edge function для перевірки `initData`) або Cloudflare Workers + D1. Вирішимо, коли дійдемо.

### Що робимо в v2.0 заради цього (дешево зараз, дорого потім)
1. Однакові 6 сфер з однаковими id — спільна мова для порівняння й спільних квестів.

6. Усе нарахування XP проходить через одну функцію (`grant`). Саме туди пізніше підключимо чергу чек-інів.
7. 5-те місце в нижній панелі зарезервоване під «Друзі».

## 10. Як тестувати dev (тільки локально)

- `npm start` → `http://localhost:5173`. Це окремий origin, тож прод-сейви звідти не видно. Демо-стан: `?dev=seed&lv=12`.
- **З телефона:** у тій самій Wi-Fi відкрити `http://<IP-мака>:5173`. Це теж окремий origin, тож безпечно.
- **Міграція на справжніх даних:** у прод-версії Профіль → Експорт (свій сейв і сейви друзів, які погодяться), у dev → Імпорт.
- **Обмеження:** локально немає Telegram (`tg = null`), тому CloudStorage не перевіриш. Через це в v2.0 код хмари (`writeCloud` / `syncCloud`) не змінюємо. Для соціалки (етапи 8–10) знадобиться тестовий бот, бо без `initData` її не перевірити.
- **Ніколи** не викладати dev на `ketalias.github.io/<будь-що>`, бо це той самий origin і ті самі сейви.

## 11. Реліз і відкат

1. Етап 0 уже на `main` і пожив 1–2 тижні.
2. Злити `dev` → `main`, підняти `VERSION` у `sw.js` (`respawn-v3`) і версію в профілі (`v2.0`).
3. На першому запуску: бекап → міграція → «Що нового».
4. Відкат: `git revert` мерж-коміту. Сейви лишаються сумісними: старі ключі сфер не переписувались, завдяки етапу 0 старий код ігнорує нові поля, плюс є бекап `respawn.v1.bak2`.
