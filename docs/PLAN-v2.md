# RESPAWN 2.0: персональна гра для всіх (план, гілка `dev`)

Мета: щоб RESPAWN підходив будь-кому, хлопцю чи дівчині, з будь-якими цілями, і лишався простим. Людина сама обирає 6 сфер, на яких росте, звертання до себе й вигляд персонажа. Прогрес тих, хто вже грає, переноситься без втрат.

---

## 1. Принципи

1. **Чужий прогрес не губимо.** Схема збереження тільки доповнюється. Нічого не видаляємо й не перейменовуємо. Перед міграцією робимо бекап.
2. **Простота.** Основний цикл такий: квест → XP → рівень → скіни. Решта (гроші, зал, фокус, розминка) — модулі, які можна ввімкнути.
3. **Персоналізація йде від вибору людини, а не від статі.** Стать (звертання) змінює тільки граматику та стартовий вигляд. Сфери, квести й скіни однакові для всіх.
4. **Скіни унісекс.** Жодних замків за статтю. Будь-яке тіло може носити будь-який одяг.

## 2. Як не зламати прогрес (найважливіше)

**Де зараз живуть збереження:**
- `localStorage['respawn.v1']`. Він прив'язаний до origin `ketalias.github.io`, тобто до всього домену, а не тільки до `/respawn/`.
- Telegram CloudStorage (окремо для кожного бота): чанки `c0…cN` + `meta`. `syncCloud()` бере той сейв, де `updatedAt` новіший.

**Ризики й рішення:**

| Ризик | Що станеться | Рішення |
| --- | --- | --- |
| Dev викладено на тому ж домені (`ketalias.github.io/щось`) | Dev-версія читає й мігрує **справжні** сейви з `localStorage` | Dev тільки локально (`npm start`) або на окремому домені (Cloudflare Pages / Netlify) + окремий тестовий бот. У коді: поза продом ключ `respawn.dev`, а не `respawn.v1` |
| Старий клієнт (закешований у Telegram на іншому пристрої) відкриває сейв v3 | `hydrate()` перекидає квести з невідомих сфер у «Дисципліну» й викидає нові ключі `stats`. `CATS[k.cat].icon` у скілах падає. Потім він заливає «новіший» зламаний сейв у хмару | **Етап 0**: хотфікс на `main` за 1–2 тижні до релізу. Старий код має терпіти невідомі сфери (див. нижче) |
| Перейменування id | Куплені скіни або вибрані квести «зникають» | Id ніколи не змінюються: `slot:key` в `owned` і `eq`, ключі сфер `biz / math / eng / dis / body` |
| Людина прибрала сферу | Втрачено XP сфери | XP сфер ніколи не стирається. Прибрана сфера йде в архів, а коли її повертають, повертається й XP |

**Етап 0, «щеплення» (маленький хотфікс на `main`):**
- `hydrate()` залишає в `stats` невідомі ключі й не чіпає невідомі `q.cat`.
- Усюди, де стоїть `CATS[x]`, додаємо фолбек `{ name: 'Інше', icon: 'star' }` (`questCard`, `mind.js` ×5).
- Поза `ketalias.github.io` використовуємо окремий ключ сховища.
- Піднімаємо `VERSION` у `sw.js`.

**Бекап і тести:**
- Перед першою міграцією на v3 записуємо копію в `localStorage['respawn.v1.bak2']`. Експорт/імпорт у профілі вже є.
- `tools/migrate-test.mjs` проганяє `hydrate()` на фікстурах: сейв v1 (str/int/vit), справжній сейв автора, сейв з грошима/тренуваннями/скілами, порожній сейв. Перевіряє, що `xp, coins, owned, eq, ach, streak, counters, money.log, workouts, prs` не змінились.

## 3. Шість сфер

**Механіка.** Сфер рівно 6, і на радарі в профілі вони складаються в шестикутник. Кожна сфера має:
- **назву**, **іконку** й **колір**, які людина може змінити;
- **архетип**. Від нього залежать підказки квестів, лінійка скінів і модулі, які пропонуються.

Перейменування, іконка й колір XP не чіпають. Якщо замінити сферу на іншу, стара йде в архів разом зі своїм XP.

**Шістка за замовчуванням для нових гравців:**

| Сфера | Що туди входить | Модуль (за бажанням) |
| --- | --- | --- |
| Тіло | спорт, сон, вода, харчування | Зал (журнал тренувань) |
| Розум | навчання, читання, мови | Фокус-сесії, Розминка мозку |
| Гроші | робота, бізнес, фінанси | Бос місяця |
| Спокій | відпочинок, медитація, щоденник, настрій | — |
| Люди | сім'я, друзі, стосунки | — |
| Порядок | дім, режим, рутина, сила волі | — |

**Бібліотека для заміни:** Кар'єра, Творчість, Мови, Догляд за собою, Духовність, Подорожі, Навчання (школа/універ), Батьківство, Інженерія/код, Музика, Спорт (профі), «Своя» (порожня).

**Квест у 2 тапи:** назва + сфера. Складність за замовчуванням «Норм», решта під «Більше». Для кожної сфери є 6–10 готових квестів, які додаються одним тапом.

**Модулі** нараховують XP у сферу, до якої прив'язані. Зараз це зашито в коді: гроші йдуть у `biz`, зал у `body`, а розминка в `math`.

**Для тих, хто вже грає:** їхні 5 сфер лишаються з тими самими id і назвами (Гроші, Математика, Інженерія, Дисципліна, Тіло), квести не змінюються. 6-ту сферу вони обирають в одному вікні «Що нового».

## 4. Стать: звертання й тіло

**Звертання** — один вибір в онбордингу: «Як до тебе звертатись?» Він / Вона.

- **Граматика.** Хелпер `g('Закрив угоду', 'Закрила угоду')`. Треба перевірити близько 20–30 рядків: бізнес-дії («Написав ліду», «Здав роботу»), тости («Відпочив»), «Готовий до підходу?», «Шукай сам», онбординг. Де можна, пишемо нейтрально.
- **Ранги в двох родах:**

| LV | Він | Вона |
| --- | --- | --- |
| 1 | NPC | NPC |
| 3 | Новачок | Новачка |
| 6 | Гравець | Гравчиня |
| 10 | Боєць | Бійчиня |
| 15 | Ветеран | Ветеранка |
| 20 | Еліта | Еліта |
| 30 | Майстер | Майстриня |
| 40 | Легенда | Легенда |
| 50 | Фінальний бос | Фінальний бос (ігровий термін) |

- Старим акаунтам поки нічого не змінюється (лишаються поточні форми), доки людина сама не обере у «Що нового».

**Тип тіла** — окремий вибір у Шафці (тіло A / тіло B). Обирається незалежно від звертання.
- Тіло B: вужчі плечі, талія, стегна. Еволюція рангу 0→3 означає підтягнутість і атлетичність, а не масу.
- Технічно: `geo()` у `sprite.js` отримує профіль тіла. `thw()` уже рахує ширину торсу по рядках, тож більшість верхів адаптуються самі. Предмети з дрібними деталями (костюм, халат, броня) перевіряємо вручну.

| Пети | собака, кролик, кактус |
| Аури | серця, сакура, зорепад |

**Нові механіки:**
- **Лінійки сфер.** Кожен архетип дає 4 нагороди на LV сфери 3 / 5 / 10 / 15. Нове джерело предмета: `src: { dir: 'body', lv: 5 }`. Приклад для Тіла: спортивний топ → гантель у руці → аура «Пульс» → золоті кроси.
- **Сукня.** Це верх із прапорцем `full: true`, який ховає низ.
- **Збережені образи.** 3 слоти, весь лук одягається одним тапом.
- **QA.** `tools/contact-sheet.mjs` генерує PNG-сітку: усі предмети × 2 тіла × 4 ступені еволюції. Так видно всі криві пікселі одразу. `sprite.js` уже працює в Node.

Ціни й старі предмети не змінюються.

## 6. Простота інтерфейсу

- **Вкладки:** База · Квести · Сфери · Шафка, плюс один модуль можна закріпити як 5-ту вкладку.
  - «Сфери» містить шестикутник, список сфер і модулі (Фокус, Розминка, Зал).
  - Тим, хто вже грає, автоматично закріплюємо «Гроші», тож вкладок так само 5 і все на звичних місцях.
- **Ачівки.** Лічильник «x / y» рахує тільки ачівки увімкнених модулів. Зароблені ніколи не зникають. Додаємо загальні ачівки сфер («Сфера до LV 5 / 10», «Усі 6 сфер до LV 3»).

### Онбординг для нових (до 60 секунд, 4 екрани)
1. Ім'я + «Як до тебе звертатись?»
2. Персонаж: тіло, тон шкіри, зачіска, колір.
3. 6 сфер: рекомендована шістка вже вибрана, тап по сфері відкриває заміну з бібліотеки.
4. Стартові квести: 1–2 пропозиції на сферу, лишаєш ті, що підходять (рекомендовано 3–6).

### «Що нового» для тих, хто вже грає (одне вікно, можна пропустити)
- Обери 6-ту сферу.
- Звертання та тип тіла.
- Огляд нових скінів.

## 7. Модель даних v3 (тільки доповнення)

```js
{
  v: 3,
  profile: { g: 'm' | 'f' | null },          // null = старий акаунт, ще не обирав → поточні форми
  dirs: [                                     // рівно 6
    { id: 'body', name: 'Тіло', icon: 'heart', color: '#ff6b6b', arch: 'body' },
    { id: 'math', name: 'Математика', icon: 'sigma', color: '#8fd3ff', arch: 'mind' }, // старий акаунт
    // …
  ],
  dirsArchive: [ /* прибрані сфери; XP лишається в stats */ ],
  mods: { money: true, gym: true, focus: true, drill: true, pin: 'money', to: { money: 'biz', gym: 'body', drill: 'math' } },
  stats: { biz: 2200, math: 1300, eng: 1700, dis: 900, body: 500, calm: 0 }, // ключ = id сфери, старі ключі не чіпаємо
  eq: { /* …як зараз…, */ body: 'a', detail: null },
  looks: [ /* { name, eq } ×3 */ ],
}
```

- Статичний `CATS` замінюємо на `dirOf(id)`. Він шукає в `S.dirs`, потім в `dirsArchive`, потім повертає фолбек.
- Міграція v2→v3: якщо `dirs` немає, а сейв не порожній, будуємо `dirs` з 5 старих категорій (ті самі id і назви), а 6-й слот лишаємо порожнім до «Що нового».

## 9. Як тестувати dev

- **Локально:** `npm start` → `http://localhost:5173`. Це окремий origin, тож прод-сейви звідти не видно. Демо-стан: `?dev=seed&lv=12`.
- **Міграція на справжніх даних:** у прод-версії Профіль → Експорт, у dev → Імпорт.
- **На телефоні / в Telegram:** гілку `dev` підключити до Cloudflare Pages або Netlify (окремий домен, автодеплой гілки) і створити окремого тестового бота в @BotFather (CloudStorage у нього своя).
- **Ніколи** не викладати dev на `ketalias.github.io/<будь-що>`, бо це той самий origin і ті самі сейви.

## 10. Реліз і відкат

1. Етап 0 уже на `main` і пожив 1–2 тижні.
2. Злити `dev` → `main`, підняти `VERSION` у `sw.js` (`respawn-v3`) і версію в профілі (`v2.0`).
3. На першому запуску: бекап → міграція → «Що нового».
4. Відкат: `git revert` мерж-коміту. Сейви лишаються сумісними: завдяки етапу 0 старий код ігнорує нові поля, плюс є бекап `respawn.v1.bak2`.
