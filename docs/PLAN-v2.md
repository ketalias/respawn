# RESPAWN 2.0: персональна гра для всіх (план, гілка `dev`)

Мета: щоб RESPAWN підходив будь-кому, хлопцю чи дівчині, з будь-якими цілями, і лишався простим. Людина сама обирає 6 сфер, на яких росте, звертання до себе й вигляд персонажа. Прогрес тих, хто вже грає, переноситься без втрат. Архітектура одразу розрахована на друзів, перегляд статистики й спільні плани.

**Прийняті рішення (14.11.2026):**
- Шістка за замовчуванням: Тіло, Розум, Гроші, Спокій, Люди, Порядок.
- Звертання тільки «Він / Вона», без нейтрального варіанта.
- Dev тестуємо тільки локально.
- Вкладки: 4 зараз (База · Квести · Сфери · Шафка). 5-те місце зарезервоване під «Друзі».

---

## 1. Принципи

1. **Чужий прогрес не губимо.** Схема збереження тільки доповнюється. Нічого не видаляємо й не перейменовуємо. Перед міграцією робимо бекап.
2. **Простота.** Основний цикл: квест → XP → рівень → скіни. Решта (гроші, зал, фокус, розминка) — модулі, які можна ввімкнути.
3. **Персоналізація йде від вибору людини, а не від статі.** Стать (звертання) змінює тільки граматику та стартовий вигляд. Сфери, квести й скіни однакові для всіх.
4. **Скіни унісекс.** Жодних замків за статтю.
5. **Офлайн спочатку, соціалка окремим шаром.** Особистий сейв і далі живе на пристрої та в Telegram. Сервер (у майбутньому) зберігатиме тільки друзів, публічні картки й спільні плани. Сейви на сервер не переїжджають, тож для поточних акаунтів нічого не ламається.

## 2. Як не зламати прогрес (найважливіше)

**Де зараз живуть збереження:**
- `localStorage['respawn.v1']`. Він прив'язаний до origin `ketalias.github.io`, тобто до всього домену, а не тільки до `/respawn/`.
- Telegram CloudStorage (окремо для кожного бота): чанки `c0…cN` + `meta`. `syncCloud()` бере той сейв, де `updatedAt` новіший.

**Ризики й рішення:**

| Ризик | Що станеться | Рішення |
| --- | --- | --- |
| Dev викладено на тому ж домені (`ketalias.github.io/щось`) | Dev-версія читає й мігрує **справжні** сейви з `localStorage` | Dev тільки локально. У коді: поза `ketalias.github.io` ключ `respawn.dev`, а не `respawn.v1` |
| Старий клієнт (закешований у Telegram на іншому пристрої) відкриває сейв v3 | `hydrate()` перекидає квести з невідомих сфер у «Дисципліну» й викидає нові ключі `stats`. `CATS[k.cat].icon` у скілах падає. Потім він заливає «новіший» зламаний сейв у хмару | **Етап 0**: хотфікс на `main` за 1–2 тижні до релізу. Старий код має терпіти невідомі сфери |
| Перейменування id | Куплені скіни або вибрані квести «зникають» | Id ніколи не змінюються: `slot:key` в `owned` і `eq`, ключі сфер `biz / math / eng / dis / body` |
| Людина прибрала сферу | Втрачено XP сфери | XP сфер ніколи не стирається. Прибрана сфера йде в архів, а коли її повертають, повертається й XP |

**Етап 0, «щеплення» (маленький хотфікс на `main`):**
- `hydrate()` залишає в `stats` невідомі ключі й не чіпає невідомі `q.cat`.
- Усюди, де стоїть `CATS[x]`, додаємо фолбек `{ name: 'Інше', icon: 'star' }` (`questCard`, `mind.js` ×5).
- Невідомі поля всередині `days[k]` і квестів не зачіпаються (перевірити).
- Поза `ketalias.github.io` використовуємо окремий ключ сховища.
- Піднімаємо `VERSION` у `sw.js`.

**Бекап і тести:**
- Перед першою міграцією на v3 записуємо копію в `localStorage['respawn.v1.bak2']`. Експорт/імпорт у профілі вже є.
- `tools/migrate-test.mjs` проганяє `hydrate()` на фікстурах: сейв v1 (str/int/vit), справжній сейв автора, сейв з грошима/тренуваннями/скілами, порожній сейв. Перевіряє, що `xp, coins, owned, eq, ach, streak, counters, money.log, workouts, prs` не змінились.
- Окремий тест «старий клієнт»: сейв v3 → `hydrate()` з етапу 0 → назад у v3, нічого не загубилось.

## 3. Шість сфер

**Механіка.** Сфер рівно 6, на радарі в профілі вони складаються в шестикутник. Кожна сфера має:
- **назву**, **іконку** й **колір**, які людина може змінити;
- **архетип** (`arch`). Від нього залежать підказки квестів, лінійка скінів і модулі, які пропонуються.

Архетип також буде **спільною мовою між друзями**. У тебе сфера може називатися «Залізо», а в друга «Спорт», але обидві мають архетип `body`. Тому статистику можна порівнювати, а квест зі спільного плану потрапляє кожному у власну сферу.

Перейменування, іконка й колір XP не чіпають. Якщо замінити сферу на іншу, стара йде в архів разом зі своїм XP.

**Шістка за замовчуванням для нових гравців:**

| Сфера | Архетип | Що туди входить | Модуль (за бажанням) |
| --- | --- | --- | --- |
| Тіло | `body` | спорт, сон, вода, харчування | Зал (журнал тренувань) |
| Розум | `mind` | навчання, читання, мови | Фокус-сесії, Розминка мозку |
| Гроші | `money` | робота, бізнес, фінанси | Бос місяця |
| Спокій | `calm` | відпочинок, медитація, щоденник, настрій | — |
| Люди | `people` | сім'я, друзі, стосунки | — |
| Порядок | `order` | дім, режим, рутина, сила волі | — |

**Бібліотека для заміни** (кожна має свій архетип): Кар'єра, Творчість, Мови, Догляд за собою, Духовність, Подорожі, Навчання (школа/універ), Батьківство, Інженерія/код, Музика, Спорт (профі), «Своя» (людина обирає найближчий архетип).

**Квест у 2 тапи:** назва + сфера. Складність за замовчуванням «Норм», решта під «Більше». Для кожного архетипу є 6–10 готових квестів, які додаються одним тапом.

**Модулі** нараховують XP у сферу, до якої прив'язані (`mods.to`). Зараз це зашито в коді: гроші йдуть у `biz`, зал у `body`, а розминка в `math`.

**Для тих, хто вже грає:** їхні 5 сфер лишаються з тими самими id і назвами, отримують архетипи й квести не змінюються:

| id | Назва | Архетип |
| --- | --- | --- |
| `biz` | Гроші | `money` |
| `math` | Математика | `mind` |
| `eng` | Інженерія | `craft` |
| `dis` | Дисципліна | `order` |
| `body` | Тіло | `body` |

6-ту сферу вони обирають в одному вікні «Що нового».

## 4. Стать: звертання й тіло

**Звертання** — один вибір в онбордингу: «Як до тебе звертатись?» Він / Вона.

- **Граматика.** Хелпер `g('Закрив угоду', 'Закрила угоду')`. Треба перевірити близько 20–30 рядків: бізнес-дії («Написав ліду», «Здав роботу»), тости («Відпочив»), «Готовий до підходу?», «Шукай сам», онбординг. Де можна, пишемо нейтрально.
- **Ранги в двох родах:**

| LV | Він | Вона |
| --- | --- | --- |
| 1 | NPC | NPC |
| 3 | Новачок | Новачка |
| 6 | Гравець | Гравчиня |
| 10 | Боєць | Бійчиня |
| 15 | Ветеран | Ветеранка |
| 20 | Еліта | Еліта |
| 30 | Майстер | Майстриня |
| 40 | Легенда | Легенда |
| 50 | Фінальний бос | Фінальний бос (ігровий термін) |

- Старим акаунтам нічого не змінюється (лишаються поточні форми), доки людина сама не обере у «Що нового».
- Звертання потрапляє в публічну картку, щоб друзі бачили правильні форми («Оля закрила 5 квестів»).

**Тип тіла** — окремий вибір у Шафці (тіло A / тіло B), незалежно від звертання.
- Тіло B: вужчі плечі, талія, стегна. Еволюція рангу 0→3 означає підтягнутість і атлетичність, а не масу.
- Технічно: `geo()` у `sprite.js` отримує профіль тіла. `thw()` уже рахує ширину торсу по рядках, тож більшість верхів адаптуються самі. Предмети з дрібними деталями (костюм, халат, броня) перевіряємо вручну.

## 6. Простота інтерфейсу

**Вкладки:**
- **Зараз 4:** База · Квести · Сфери · Шафка. Профіль, як і раніше, відкривається через аватар у шапці.
- **У майбутньому 5-та:** Друзі (картки друзів і спільні плани).
- **«Сфери»:** шестикутник, список сфер, усі модулі (Гроші, Фокус, Розминка, Зал).
- **Закріплені модулі.** Модуль можна закріпити, і тоді його картка стоїть на Базі. «Бос місяця» й «Розминка» вже мають такі картки. Тим, хто вже грає, автоматично закріплюються всі їхні модулі, тож до Грошей так само один тап.

**Ачівки.** Лічильник «x / y» рахує тільки ачівки увімкнених модулів. Зароблені ніколи не зникають. Додаємо загальні ачівки сфер («Сфера до LV 5 / 10», «Усі 6 сфер до LV 3»).

### Онбординг для нових (до 60 секунд, 4 екрани)
1. Ім'я + «Як до тебе звертатись?»
2. Персонаж: тіло, тон шкіри, зачіска, колір.
3. 6 сфер: рекомендована шістка вже вибрана, тап по сфері відкриває заміну з бібліотеки.
4. Стартові квести: 1–2 пропозиції на сферу, лишаєш ті, що підходять (рекомендовано 3–6).

### «Що нового» для тих, хто вже грає (одне вікно, можна пропустити)
- Обери 6-ту сферу.
- Звертання та тип тіла.
- Огляд нових скінів.

## 7. Модель даних v3 (тільки доповнення)

```js
{
  v: 3,
  profile: { g: 'm' | 'f' | null },          // null = старий акаунт, ще не обирав → поточні форми
  dirs: [                                     // рівно 6
    { id: 'body', name: 'Тіло', icon: 'heart', color: '#ff6b6b', arch: 'body' },
    { id: 'math', name: 'Математика', icon: 'sigma', color: '#8fd3ff', arch: 'mind' }, // старий акаунт
    // …
  ],
  dirsArchive: [ /* прибрані сфери; XP лишається в stats */ ],
  mods: { money: true, gym: true, focus: true, drill: true, home: ['money', 'drill'], to: { money: 'biz', gym: 'body', drill: 'math' } },
  stats: { biz: 2200, math: 1300, eng: 1700, dis: 900, body: 500, calm: 0 }, // ключ = id сфери, старі ключі не чіпаємо
  days: { '2026-11-14': { xp: 120, q: 4, w: 1, s: { body: 60, biz: 60 } } },  // нове: s = XP по сферах за день
  quests: [ { /* …як зараз…, */ plan: null } ],   // нове: посилання на спільний план (майбутнє)
  eq: { /* …як зараз…, */ body: 'a', detail: null },
  looks: [ /* { name, eq } ×3 */ ],
  privacy: { card: 'friends', spheres: true, heat: true, money: false, quests: false }, // діє, коли з'являться друзі
}
```

- Статичний `CATS` замінюємо на `dirOf(id)`. Він шукає в `S.dirs`, потім в `dirsArchive`, потім повертає фолбек.
- Міграція v2→v3: якщо `dirs` немає, а сейв не порожній, будуємо `dirs` з 5 старих категорій (ті самі id і назви, архетипи з таблиці в розділі 3), а 6-й слот лишаємо порожнім до «Що нового».
- `days[k].s` пишеться тільки з v3 далі, старі дні не чіпаємо. Щоб CloudStorage не розросталась, дні, старші за рік, згортаємо до `{ xp, q, w }`.
- Нові сфери, які людина створює сама, отримують id з `crypto.randomUUID()`, щоб не було колізій при обміні з друзями.

## 8. Соціальна частина: що закладаємо вже зараз

Друзів, статистики й спільних планів у v2.0 ще **не буде**, але v2.0 проєктуємо так, щоб їх можна було додати без нової міграції сейвів.

### Що з'явиться пізніше
- **Друзі.** Запрошення посиланням у Telegram (`t.me/<bot>/<app>?startapp=f_<код>`), список друзів, картка кожного: персонаж у скінах, LV і ранг, 6 сфер за архетипами, стрік, ачівки, теплова карта.
- **Статистика.** «Цього тижня»: XP по сферах у тебе та друзів, хто тримає стрік.
- **Спільні плани.** 1–5 квестів, кілька людей і строк (наприклад, 30 днів). Кожен відмічає у себе, усі бачать прогрес команди. Якщо всі закрили день, кожен отримує бонус «Командний ідеальний день». Квест плану потрапляє кожному в його сферу з тим самим архетипом.

### Архітектура
```
Пристрій (як зараз)                    Сервер (майбутнє, окремий шар)
────────────────────                   ──────────────────────────────
localStorage + Telegram CloudStorage   users     (tg_id, name, g, card, card_at)
повний особистий сейв                  friends   (a, b, status)
            │                          plans     (id, owner, title, quests, until)
            │  публікує картку,        members   (plan, user)
            │  чек-іни квестів плану   checkins  (plan, pq, user, d)
            └───────────────────────►  доступ: бачиш тільки друзів і свої плани
```
- **Особа = Telegram user id.** Сервер перевіряє підпис `initData` (HMAC токеном бота). Логінів і паролів немає.
- Хто відкриває сайт поза Telegram, грає як зараз, а для соціалки підключає Telegram.
- **Публічна картка — чиста функція** `publicCard(S, privacy)`. Без сум грошей і назв квестів (якщо людина сама не дозволить). Сервер не бачить особистого сейву.
- **Офлайн.** Чек-іни квестів плану складаються в чергу всередині сейву й відправляються, коли з'явиться мережа.
- **Бекенд:** Supabase (Postgres + edge function для перевірки `initData`) або Cloudflare Workers + D1. Вирішимо, коли дійдемо. Для статичного сайту підходять обидва.

### Що робимо в v2.0 заради цього (дешево зараз, дорого потім)
1. Архетипи сфер — спільна мова для порівняння й спільних квестів.
2. `days[k].s` — тижнева статистика по сферах з'явиться без нової міграції.
3. `profile.g` — правильні форми в картках друзів.
4. `privacy` у сейві з першого дня, а UI з'явиться разом із друзями.
5. `q.plan` — квест знає, що він зі спільного плану.
6. Усе нарахування XP проходить через одну функцію (`grant`). Саме туди пізніше підключимо чергу чек-інів.
7. 5-те місце в нижній панелі зарезервоване під «Друзі».

## 10. Як тестувати dev (тільки локально)

- `npm start` → `http://localhost:5173`. Це окремий origin, тож прод-сейви звідти не видно. Демо-стан: `?dev=seed&lv=12`.
- **З телефона:** у тій самій Wi-Fi відкрити `http://<IP-мака>:5173`. Це теж окремий origin, тож безпечно.
- **Міграція на справжніх даних:** у прод-версії Профіль → Експорт (свій сейв і сейви друзів, які погодяться), у dev → Імпорт.
- **Обмеження:** локально немає Telegram (`tg = null`), тому CloudStorage не перевіриш. Через це в v2.0 код хмари (`writeCloud` / `syncCloud`) не змінюємо. Для соціалки (етапи 8–10) знадобиться тестовий бот, бо без `initData` її не перевірити.
- **Ніколи** не викладати dev на `ketalias.github.io/<будь-що>`, бо це той самий origin і ті самі сейви.

## 11. Реліз і відкат

1. Етап 0 уже на `main` і пожив 1–2 тижні.
2. Злити `dev` → `main`, підняти `VERSION` у `sw.js` (`respawn-v3`) і версію в профілі (`v2.0`).
3. На першому запуску: бекап → міграція → «Що нового».
4. Відкат: `git revert` мерж-коміту. Сейви лишаються сумісними: завдяки етапу 0 старий код ігнорує нові поля, плюс є бекап `respawn.v1.bak2`.
